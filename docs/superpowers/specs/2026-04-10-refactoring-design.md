# 重构设计归档记录

## 1. 文档身份

- 文档类型：归档文档
- 约束级别：不直接约束当前实现
- 适用范围：仅用于保留历史重构背景

本文件记录一次历史性的重构思路与阶段性目标。

## 2. 当前使用规则

- 本文件**不是**当前目录结构、模块职责或实现边界的直接依据。
- 如果本文件中的路径、目录、命名或重构建议与当前代码不一致，应以当前代码、主 spec 与对应 feature spec 为准。
- 如果希望复用本文件中的某个思路，必须先把该思路转写到当前主 spec 或对应 feature spec，再进入实现。

## 3. 归档原因

该文档包含历史时期的重构设想，其中部分文件名、目录形态与当前仓库现状已经不一致。

为避免旧设计误导当前实现，本文件仅保留为历史背景记录，不再继续维护为当前规范文档。

## 4. 可保留的信息类型

以下内容仍可作为参考：

- 对维护性优先、渐进式重构的总体思路
- “先稳边界，再拆文件”的方法论
- 对历史重构阶段的背景说明

以下内容不得直接作为当前实现依据：

- 旧目录结构
- 旧文件名
- 旧 provider / service 拆分方案
- 未落地的未来重构计划

## 5. 后续要求

如果未来确实需要再次制定重构方案，应新建或更新当前有效 spec，而不是继续在本归档文档上追加当前约束。
